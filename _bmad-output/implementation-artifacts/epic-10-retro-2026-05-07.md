## What Went Well

### 1. test-support Module Became the Backbone of Quality

Story 10.1 transformed `test-support` from a sparse helper module into the project's quality foundation: `@IntegrationTest` and `@ContractTest` composite annotations, singleton container configs (Postgres, Kafka, Redis, Elasticsearch, Keycloak 26.x, Schema Registry), `TestData` builders with `OrderBuilder`/`CartItemBuilder`/`InventoryItemBuilder`, `SagaTestHelper`, `EventAssertions` (AssertJ-style for `SpecificRecord`), and `RoboMartLayerArchTest` (interface-based ArchUnit inheritance). Every service now reuses the same primitives — no per-service container drift.

### 2. ArchUnit Caught Real Layer Violations

Story 10.4's `RoboMartLayerArchTest` immediately flagged two production-critical violations:
- `OrderAdminRestController` calling `orderItemRepository.findByOrderId()` and `orderStatusHistoryRepository.findByOrderIdOrderByChangedAtAsc()` directly
- `PaymentAdminRestController` calling `paymentRepository.findByOrderId()` directly

Both were refactored into service-layer methods (`OrderService.getOrderItemCount()`, `OrderService.getOrderStatusHistory()`, `PaymentService.findByOrderId()`). The COUNT-vs-loadAll improvement from review patch (`countByOrderId` JPA method) became a measurable performance win. ArchUnit paid for itself on its first run — exactly the value proposition.

### 3. k6 Performance Tests Encoded the NFRs as Pass/Fail Thresholds

Story 10.3 turned NFR3 (saga < 3s) and NFR6 (no oversell, exactly 1 winner in flash sale) from prose targets into k6 thresholds:
- `saga_completion_time` p95 < 3000ms
- `oversell_errors` count == 0
- `successful_orders` count == 1 in flash sale
- `out_of_stock_responses` >= 99
- `duplicate_charges` == 0

Review patches sharpened the metrics: `concurrent-orders.js` switched from arrival-rate (10 req/s) to `shared-iterations vus:100, iterations:100` to actually match "100 concurrent"; `sagaCompletionTime` start was moved to AFTER 2xx accepted to stop polling-sleep inflating the metric.

### 4. Chaos Engineering Within Spring Boot 4 Reach

Chaos Monkey 4.0.0 turned out to be Spring Boot 4 compatible (released using SB 4.0.2 internally), so the fallback custom-AOP path in Story 10.3 Task 8 was never needed. `ServiceKillChaosIT` exercises both AC4 (kill `robomart-payment-service` mid-saga, verify recovery within 60s) and AC5 (500ms latency injection via `/actuator/chaosmonkey/assaults`). Review-driven patches added `@AfterEach` cleanup so a failing test cannot leave a service stopped or chaos enabled — the test suite is self-healing.

### 5. CI/CD Pipelines + Quality Gates Closed the Loop

Story 10.4 delivered four GitHub Actions workflows (`ci-backend`, `ci-frontend`, `schema-compatibility`, `cd-deploy`) plus 7 multi-stage Dockerfiles and K8s rolling-update strategy (`maxUnavailable: 0`) on every deployment. Review patches converted the deploy from fragile `sed` manifest mutation to `kubectl set image` per deployment, and made `cd-deploy` consume `workflow_run` from `Backend CI` so deploys cannot run on red builds. The `<15 min` SLA (NFR49) is now a measurable promise rather than aspiration.

### 6. Story Sequencing Made Dependencies Cooperate

10.1 → 10.2 → 10.3 → 10.4 ordering let each story consume the previous one's output: 10.1 created `@ContractTest` and `SchemaRegistryContainerConfig`, which 10.2 needed for Pact provider tests and `AvroSchemaCompatibilityIT`. 10.3 spun up the `e2e-tests` module that 10.4's CI pipeline learned to skip by default. 10.4's ArchUnit landed in `test-support` (created in 10.1) without circular dependency.

### 7. Closing the 80% JaCoCo Threshold Forced Latent Coverage Holes Closed

Story 10.1's coverage push added `CartControllerTest`, `InventoryControllerTest`, `ProductRestControllerTest`, `AdminProductRestControllerTest`, `OrderGrpcServiceTest`, `ReleaseInventoryStepTest`, `DlqAdminRestControllerTest`, `AdminSystemHealthRestControllerTest`, `NotificationServiceExtendedTest`, `CorsConfigTest`. Two follow-up commits (`d9ea5f8`, `cb21360`) tightened common-lib AuditAspect branch coverage and product-service to push every module above 80%. Coverage is now CI-enforced, not vibes.

## What Could Be Better

### 1. Pre-existing Test Hygiene Carried Over (W1, W2, W3 from 10.1)

Story 10.1 surfaced widespread style violations in pre-existing tests: 80+ test methods don't follow `should{Expected}When{Condition}()`, multiple files still use JUnit `assertDoesNotThrow`/`assertThrows` instead of AssertJ, and 14 order-service unit test files still use `new Order()` + setters instead of `TestData.order()`. All deferred — none break correctness, but they erode the quality narrative the new tests establish. A single-day "test hygiene" pass would close it; never scheduled.

### 2. Pact Test Coverage Is Narrow

Only one consumer-provider pair was wired: Notification Service → Order Service + Notification Service → Product Service. Cart→Inventory, Order→Inventory (gRPC, separate concern), Order→Payment (gRPC), and Admin→all REST relationships have no contract enforcement. The pattern is proven, but the coverage matrix is sparse.

### 3. Avro Compatibility Test Is Trivially Passing (Deferred D1 from 10.2)

`AvroSchemaCompatibilityIT.allSchemasAreBackwardCompatibleWithRegisteredVersion()` registers a schema and immediately checks it against itself — trivially compatible. Real backward-evolution tests need a fixture of historical schema versions, which was scoped out. The CI gate is real, but the assertion is weak until evolution scenarios are seeded.

### 4. Chaos Monkey Operates at the Spring Layer, Not the gRPC Wire (Deferred 10.3 W3)

`chaos.monkey.watcher.service=true` intercepts Spring `@Service` proxies, not the gRPC Netty transport. So AC5's "500ms latency on inter-service gRPC calls" is approximated, not exact. Real wire-level chaos requires Toxiproxy or a gRPC interceptor — an architectural investment we explicitly deferred.

### 5. K8s Liveness-Probe Recovery Is Not Exercised (Deferred 10.3 W1)

`ServiceKillChaosIT` uses `docker stop/start` because Docker Compose doesn't model K8s probe semantics. NFR34's "services restart via K8s liveness probes" is asserted-by-proxy, not directly exercised. A `kind`/`minikube` lift would unlock real probe testing — out of scope here.

### 6. CI Timeout Margin Is Thin (Deferred 10.4 W2)

`ci-backend.yml` sets `timeout-minutes: 20` against an NFR49 SLA of <15 min. Expected timing on warm cache is ~14 min — any cache miss or slow Testcontainers startup blows the SLA before the timeout fires. We have no measured CI timing data yet to tune. First red build under load will tell us.

### 7. ArchUnit `@BatchMapping` Exclusion Uses String Annotation Match (Deferred 10.4 W1)

The predicate excluding GraphQL DataLoader controllers from "no controller→repository" rule matches the annotation by FQN string. If ArchUnit's class loading or annotation scanning ever changes behavior, this exclusion silently fails and produces false positives. Fragile by design; documented in Dev Notes.

### 8. OpenAPI Drift Detection Is Build-Cycle Heavy

`springdoc-openapi-maven-plugin` was originally added then removed (10.4 review decision) because Spring Boot 4 compatibility was unverified. The drift script (`check-openapi-drift.sh`) now exists but the spec-generation half is missing — the gate is one-legged until specs are produced, either by a `@SpringBootTest` that writes `target/openapi.json` or by a verified plugin.

### 9. Five Epics Without a Formal Retro

Epics 6, 7, 8, 9 shipped without a written retro. Lessons made it into deferred-work.md and code-review patches, but the cadence broke. This retro is the project's first chance in five epics to consolidate cross-epic patterns — that's a long blind spot.

## Key Insights

### Patterns That Held

1. **Singleton Testcontainers via static init + `@TestConfiguration(proxyBeanMethods=false)`** — set in 10.1, reused unchanged everywhere; no per-service container drift after 10 epics.
2. **Interface-based ArchUnit (`RoboMartLayerArchTest`)** — service test classes are 3 lines; rules evolve in one place. The pattern scales linearly with new services.
3. **Composite test annotations (`@IntegrationTest`, `@ContractTest`)** — service authors don't manage container imports; intent is declarative.
4. **k6 thresholds as NFR contracts** — turning prose NFRs into `thresholds: { 'saga_completion_time': ['p(95)<3000'] }` makes "did we meet the spec?" mechanically answerable.
5. **`@EnabledIfSystemProperty` + `*IT.java` + `skipE2ETests` flag** — keeps full-stack tests out of Surefire/normal CI but available on demand.

### Anti-Patterns Avoided

1. Did not introduce a custom AOP chaos framework when Chaos Monkey 4.0.0 turned out compatible — saved a `common-lib/chaos/` permanent fixture.
2. Did not add Helm chart creation to Story 10.4 scope (kept it focused on raw `kubectl apply` against existing manifests). Helm migration is a deliberate post-project step, not a scope creep risk.
3. Did not block CI pipeline on E2E tests — the explicit `-DskipE2ETests=true` default means CI cannot block on flakiness from a full Docker stack.
4. Did not couple the deploy workflow's `kubectl set image` to manifest mutation — the deploy is now stateless w.r.t. the runner's local files.

### Process Insights

- **Story 10.1's job was to make Story 10.2/10.3/10.4 cheap.** It paid off: every later story consumed primitives instead of inventing them.
- **Code review continued to be the dominant quality lever.** Even in a QA-focused epic where one might expect tests-as-spec to suffice, reviews caught Pact body mismatches, NPE-on-COUNT, race conditions in test fixtures, fragile JSON parsing — issues no automated suite would catch by itself.
- **Skipping retros for 4 epics was a real cost.** Lessons did not vanish, but the meta-pattern view (which only retros provide) was unavailable from Epic 5 to Epic 10.

5. **Patterns reused, not reinvented**. Pinia store template, admin controller convention, outbox poller, Redis distributed lock, structured logging, correlation-ID propagation, singleton container config — established once, applied consistently.

### What Would Be Done Differently If Starting Over

1. **Establish `test-support` and `@IntegrationTest` in Epic 1, not Epic 10.** Several services accreted ad-hoc Testcontainers boilerplate from Epic 2-9 that 10.1 had to retrofit. If singletons + composite annotations existed from day 1, ~60% of integration test code in Epic 2-9 would have been simpler.
2. **Stand up CI early — at least `ci-backend.yml` after Epic 1.** Shipping "no production incidents" across 10 epics was a positive outcome but largely thanks to local discipline; CI as a safety net is more durable than discipline. ArchUnit, JaCoCo, Checkstyle should have gated PRs from Story 1.x.
3. **Decide common-lib split in Epic 1.** Three frontend consumers, 7 backend services, Avro/proto generated code, security-lib all share or sit beside it. Splitting in Epic 1 would have been one day of work; splitting now is an entire mini-epic with regression risk. Procrastination compounded.
4. **Write retros every epic, even short ones.** Skipping Epic 6, 7, 8, 9 retros traded near-term velocity for blurred meta-pattern recognition. A 30-minute retro per epic compounds.
5. **Define NFRs as test thresholds before implementing the feature.** k6 thresholds in Story 10.3 felt like "documenting what we built." If concurrent-orders + flash-sale k6 scripts had existed before Epic 4, saga implementation would have had a continuous fitness function instead of an end-of-project audit.
6. **Pact contract tests should follow each new consumer-provider pair, not all-at-once at the end.** The current narrow Pact coverage is an artifact of late introduction; per-pair contract tests during Epic 4-7 would have been incremental.
7. **Pin chaos-injection strategy at the gRPC boundary from day 1**, e.g., Toxiproxy in `infra/docker/`. Chaos Monkey's service-layer interception is a compromise driven by late introduction.

### Risk Assessment

The project ships with **no critical-severity debt that blocks safe single-instance operation**. The medium-risk items cluster around two themes:
1. **Multi-pod / horizontal-scale safety** (dead-saga lock, outbox poller lock, multi-instance race conditions). The system is correct on a single replica; horizontal scale is gated on these locks.
2. **Production-grade exposure** (TLS, imagePullSecrets, defense-in-depth). The system is functionally complete; production hardening is a separate readiness gate.

The cumulative deferred count (~85 items) is manageable in absolute terms — most are quality-of-life and depth items, not correctness gaps. No item flagged as critical-severity in any retrospective is unaddressed.
